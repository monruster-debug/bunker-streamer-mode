# Бункер - режим стримера

Независимое расширение Manifest V3 для Chrome, Edge и Яндекс Браузера. Основной интерфейс игры остаётся во вкладке shelter42.ru. Камеры и видимые игровые данные выводятся в отдельном окне, которое стример захватывает в OBS через «Захват окна». Зрители смотрят обычную трансляцию, расширение им не требуется.

## Установка

1. `npm install` и `npm run build`.
2. В `chrome://extensions` включить режим разработчика → «Загрузить распакованное расширение» → выбрать папку `dist`.
3. Открыть комнату на shelter42.ru и нажать значок расширения.
4. Кнопка «Демо на 12 мест» позволяет проверить композицию без сервера и камер.

## Видеосвязь

Нужен LiveKit Cloud либо собственный LiveKit с TLS и TURN. Секрет LiveKit хранится только на сервере выдачи токенов. Скопируйте `.env.example` в `.env`, заполните параметры и выполните `npm run server`. Для удалённых участников опубликуйте сервер токенов по HTTPS через reverse proxy; по умолчанию он слушает только localhost.

Для комнаты задайте до 12 разных случайных ключей игроков в ROOMS_JSON и отдельный ключ просмотра. Один ключ = один слот: повторное подключение того же слота заменяет предыдущую сессию. Раздавайте каждому игроку только его ключ. Подключение в роли «Стример» не публикует камеру; если стример играет, он использует роль игрока. До 12 публикующих слотов и до 20 соединений суммарно. Ключи комнаты вводятся при подключении и не сохраняются расширением. Для публичного размещения добавьте ограничение запросов на reverse proxy.

Игроки вводят одинаковые адрес сервера и комнату, каждый свой ключ и имя. Камера/микрофон включаются после подключения с разрешения браузера. Окно видеостола нужно держать открытым: его закрытие отключает камеру. Звук выводится в этом окне; не включайте одновременно ещё одну голосовую связь с теми же участниками. OBS должен захватывать звук окна/приложения отдельно. «Режим для стрима» скрывает настройки; Escape возвращает их. Не показывайте ввод ключей в эфире.

## Синхронизация игры — ещё требует интеграции

Исходников сайта нет, поэтому адаптер читает только видимый текст DOM из исходной вкладки каждые 1,5 секунды. CSS-селекторы задаются в «Синхронизация с сайтом». Автоматическое определение стадий, точная привязка игроков, голосование, таймер и статусы исключения **ещё не реализованы и не проверены** в реальной комнате. В текущем прототипе карточки сопоставляются камерам по порядку появления; это нужно заменить стабильными ID сайта перед настоящей трансляцией. Данные у стримера считываются из его собственной игровой вкладки, а не из браузеров других игроков. Закрытые карты и внутреннее состояние сайта не извлекаются.

Следующий шаг — изучить DOM действующей комнаты на всех стадиях (лобби, раскрытие, обсуждение, голосование, исключение, финал), реализовать проверенный адаптер с привязкой ID, добавить таймер и явное предупреждение об устаревших данных. Сайт не изменяется, игровые действия выполняются в основном интерфейсе.

## Проверки

`npm run check` проверяет лимит 12 публикующих слотов и разграничение ролей. `npm run build` собирает локальный SDK без удалённых скриптов. Реальные камеры, соединение 12 участников, права доступа расширения, OBS и совместимость с DOM игры требуют ручной проверки с настроенным LiveKit. Это первая техническая версия, не готовый релиз.

## Обновление синхронизации

Добавлено предварительное автоматическое чтение раздела «Подробная таблица открытых карт» по заголовку и видимым строкам. Адаптер не читает состояние приложения и панель личных карт. Разметка DOM реальной комнаты ещё требует проверки: если таблица не найдена, задайте селектор контейнеров игроков и селектор имени внутри каждого контейнера вручную.

Карточки теперь сопоставляются по уникальному имени в игре, независимо от порядка подключения камер. Введите такое же имя при подключении к видеостолу. Совпадающие имена и старые позиционные данные не сопоставляются. Стабильные ID сайта пока не интегрированы.

Состояние передаётся каждые 1,5 секунды, даже если карты не изменились. Через 15 секунд без обновления видеостол предупреждает об устаревших данных. Браузер может замедлять фоновые вкладки; предупреждение в этом случае ожидаемо. Для таймера добавлен ручной CSS-селектор. Этап, раунд, катастрофа и убежище по-прежнему требуют селекторов; автоматическое голосование и статусы исключения не реализованы.

После сборки обновите расширение в chrome://extensions и перезагрузите вкладку игры. Затем откройте новый видеостол значком расширения из вкладки комнаты. Проверяйте трансляцию только после ручного сравнения открытых карт с игрой.
